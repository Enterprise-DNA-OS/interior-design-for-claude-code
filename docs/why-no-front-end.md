# Why no front end

A studio's specifications, approvals, delivery dates and supplier costs are structured records. The weekly review can read them directly and draft the next action. The database is the product. A coding agent is one way to ask it questions.

npm run view produces read-only HTML for the week, procurement, project money and evidence checks. npm run docs produces client schedules, purchase order drafts, delivery records and approval registers. These are local documents, not an interactive application. The client schedule keeps trade costs private.

A visual design tool gives you image arranging, drag and drop, mood boards, mobile capture, offline site work and client self-service approval. This base does not supply those experiences. Images are retained as references, not downloaded or arranged into presentations. If those are central to your team, scope the visual tools and connected workflows in your customised version before replacing your existing service.

The base remains useful for specification and procurement administration without a front end. Enterprise DNA can build a client portal, branded presentation workflow, mobile capture or accounting connection around your records as part of your version. Those are scoped work, not features claimed to exist in this download.
